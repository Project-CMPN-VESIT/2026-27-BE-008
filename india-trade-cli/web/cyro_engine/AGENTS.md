## 1. Architecture Overview & Workflow

The CYRO engine (`web/cyro_engine`) executes an **Evidence-First Multi-Agent Investment Committee** graph built on **LangGraph StateGraph**.

```
                           [User Prompt]
                                 │
                                 ▼
                     ┌───────────────────────┐
                     │  Role 1: Intent Router │
                     └───────────┬───────────┘
                                 │ Plan + Horizon
                                 ▼
                     ┌───────────────────────┐
                     │Role 2: Context Builder│
                     └───────────┬───────────┘
                                 │ Raw Multi-Source Context
                                 ▼
                     ┌───────────────────────┐
                     │  Role 3: Quality Gate  │
                     └───────────┬───────────┘
                                 │ Verified Context Snapshot
                                 ▼
           ┌─────────────────────┬─────────────────────┐
           │ Parallel Fan-out via LangGraph Send API   │
           ▼                     ▼                     ▼
     ┌───────────┐         ┌───────────┐         ┌───────────┐
     │  Role 4:  │         │  Role 5:  │         │ Role 6,7,8│
     │Fundamental│         │  Filings  │         │ Technical,│
     │  Analyst  │         │Governance │         │Peer, News │
     └─────┬─────┘         └─────┬─────┘         └─────┬─────┘
           │                     │                     │
           └─────────────────────┼─────────────────────┘
                                 │ Upstream Claims
                                 ▼
                     ┌───────────────────────┐
                     │ Role 9: Risk & Bear   │
                     └───────────┬───────────┘
                                 │ All Claims + Bear Case
                                 ▼
                     ┌───────────────────────┐
                     │Role 10: Committee &   │
                     │  Citation Validator   │
                     └───────────┬───────────┘
                                 │
                                 ▼
                       [FinalResearchReport]
```

### Core Execution Flow:
1. **Deterministic Pre-Processing**: Roles 1–3 structure the research plan, gather multi-source data, filter stale metrics, and assign cryptographically unique `evidence_id` tokens (e.g. `ev_quote_01`, `ev_dcf_01`).
2. **ReAct Specialist Execution**: Roles 4–8 run in parallel as LangGraph ReAct agents (`create_react_agent`) powered by Mistral AI, calling deterministic Python computation tools and vector search tools before generating structured claims.
3. **Adversarial Risk Evaluation**: Role 9 ingests all claims generated by upstream specialists and actively attempts to break the thesis using Value-at-Risk (VaR), debt/pledge scrutiny, and macro headwinds.
4. **Horizon-Weighted Synthesis**: Role 10 synthesizes all claims according to the user's investment horizon and strictly validates every cited evidence ID against the immutable registry.

### Role 1: Intent Router
- **Module**: [`graph.py`](file:///d:/cyro/FinPilot/india-trade-cli/web/cyro_engine/graph.py#L108-L172)
- **Type**: Structured LLM Routing Node
- **Description & Purpose**: Parses the user's natural language prompt, resolves canonical NSE stock tickers (e.g. mapping "RIL" to `RELIANCE`), infers the target investment horizon (`short_term`, `swing`, `medium_term`, `long_term`), selects the research focus areas, and determines which specialist agents must run.
- **Tools Used**: None (uses LLM schema extraction + `_resolve_ticker` regex/alias dictionary).
- **Example Execution**:
  - **Input Query**: *"Should I buy Tata Motors for a 6 month swing trade?"*
  - **Output Plan**:
    ```json
    {
      "research_type": "company_research",
      "symbol": "TATAMOTORS",
      "exchange": "NSE",
      "horizon": "swing",
      "focus": ["technical setup", "results", "news/catalyst", "risk"],
      "required_context": ["market", "technical", "financials", "news"],
      "run_agents": ["fundamental", "filings_governance", "technical", "sector_peer_macro", "news_catalyst"]
    }
    ```

### Role 10: Investment Committee & Citation Gate
- **Module**: [`graph.py`](file:///d:/cyro/FinPilot/india-trade-cli/web/cyro_engine/graph.py#L336-L450) (`committee_node` & `citation_validator_node`)
- **Type**: Horizon-Weighted Synthesis Engine + Post-Execution Verifier
- **Description & Purpose**:
  1. Synthesizes all specialist claims using dynamic horizon weighting rules:
     - **`short_term`**: Highest weight = Technicals, News/Catalysts, Risk; Supporting = Sector/Peers; Lower = Fundamentals, Filings.
     - **`swing`**: Highest weight = Technicals, News, Sector/Peer, Risk; Supporting = Fundamentals.
     - **`medium_term`**: Balanced weights across Fundamentals, Technicals, News, Sector, Risk; Filings mandatory.
     - **`long_term`**: Highest weight = Fundamentals, Filings/Governance, Sector/Peer, Risk; Technicals are secondary context.
  2. Issues an institutional stance: `Constructive`, `Neutral`, `Cautious`, or `Watch for Confirmation` (disallowing direct trading buy/sell advice).
  3. Strict post-committee verification removes any hallucinated or unverified evidence IDs from every claim.
- **Example Final Report Summary**:
  ```json
  {
    "research_id": "cyro_default_89f3a1b2",
    "symbol": "INFY",
    "horizon": "long_term",
    "conclusion": "Constructive",
    "confidence": 84,
    "summary": "Long-term investment outlook is Constructive. Compelling fundamental quality (9/9 Piotroski, 14.2% DCF margin of safety, 0% promoter pledge) and 12% PE discount vs peers outweigh macroeconomic headwinds from US interest rate uncertainty."
  }
  ```

### A. Valuation Tools
**Source File**: [`web/cyro_engine/tools/valuation_tools.py`](file:///d:/cyro/FinPilot/india-trade-cli/web/cyro_engine/tools/valuation_tools.py)

#### 1. `run_dcf_valuation(symbol: str, growth_rate: float = 12.0, wacc: float | None = None) -> str`
- **Description**: Executes a 2-stage Discounted Cash Flow valuation with automated WACC estimation and Gordon Growth Model terminal value.
- **Implementation**:
  - Calls `analysis.dcf.compute_dcf_value` and `analysis.dcf.compute_wacc`.
  - Calculates WACC using CAPM: $r_e = r_f + \beta \times ERP$, where $r_f$ is the 10-year Indian G-Sec yield (7.0%), ERP is 6.5%, and tax-adjusted cost of debt.
  - Projects Free Cash Flow to Firm (FCFF) for 5 years at `growth_rate`, then discounts terminal value at 4.0% perpetual growth.
- **Functional Readiness**:
  - **Status**: **Fully Functional / Production Ready** (100% Deterministic).
  - **Data Source**: Screener.in / yfinance via `analysis.fundamental.analyse`.
  - **Failure Mode / Fallback**: Returns structured JSON error if financial statements lack FCF data.

#### 2. `compute_graham_number(symbol: str) -> str`
- **Description**: Computes Benjamin Graham's classic intrinsic value floor: $\text{Graham Number} = \sqrt{22.5 \times \text{EPS} \times \text{BVPS}}$.
- **Implementation**:
  - Calls `analysis.fundamental.analyse(symbol)`.
  - Estimates EPS and Book Value Per Share (BVPS) from current market price, P/E, and P/B ratios.
  - Computes discount/premium % against current price.
- **Functional Readiness**:
  - **Status**: **Fully Functional**.
  - **Data Source**: Screener / yfinance fundamental snapshot.

#### 3. `compute_pe_premium(symbol: str) -> str`
- **Description**: Evaluates valuation multiple expansion/compression by comparing current trailing & forward P/E against curated Indian sector medians.
- **Implementation**:
  - Uses an internal dictionary of 12 Indian sector median P/E benchmarks (e.g. IT: 25.0x, Banking: 15.0x, Consumer Defensive: 40.0x).
  - Computes percentage divergence and tags verdict (`PREMIUM`, `FAIR VALUE`, or `DISCOUNT`).
- **Functional Readiness**:
  - **Status**: **Fully Functional**.
  - **Data Source**: `analysis.fundamental.analyse`.

#### 4. `get_fundamental_snapshot(symbol: str) -> str`
- **Description**: Fetches 30+ fundamental metrics spanning Valuation (PE, PB, EV/EBITDA), Profitability (ROE, ROCE, NPM), Growth, Balance Sheet Health (D/E, Current Ratio, Interest Coverage, FCF), Ownership (Promoter %, Pledge %, Institutional %), and Analyst Ratings.
- **Implementation**:
  - Calls `analysis.fundamental.analyse(symbol)`.
  - Primary source: Screener.in web scraper; secondary fallback: yfinance.
- **Functional Readiness**:
  - **Status**: **Fully Functional**.
  - **Data Source**: Screener.in HTTP scraper with cookie management and yfinance fallback.

#### 5. `compute_financial_health(symbol: str) -> str`
- **Description**: Computes a multi-factor financial forensic score including Piotroski F-Score (0–9), Altman Z-Score (Safe/Grey/Distress zones), DuPont 3-way ROE decomposition, and CFO-to-EBITDA earnings quality ratio.
- **Implementation**:
  - Calls `analysis.financial_health.full_health_report(symbol)`.
  - Computes exact line-item balance sheet / P&L differentials.
- **Functional Readiness**:
  - **Status**: **Fully Functional / Production Ready**.
  - **Data Source**: Screener.in / yfinance financials.

### B. Data & Exchange Tools
**Source File**: [`web/cyro_engine/tools/data_tools.py`](file:///d:/cyro/FinPilot/india-trade-cli/web/cyro_engine/tools/data_tools.py)

#### 6. `get_live_quote(symbol: str) -> str`
- **Description**: Fetches real-time market quotes (LTP, previous close, percentage change, day's range, 52-week high/low, traded volume).
- **Implementation**:
  - Calls `market.nse_client.nse_client.get_quote(symbol)`.
  - Requests NSE public API endpoint with automated session/cookie rotation.
- **Functional Readiness**:
  - **Status**: **Fully Functional**.
  - **Data Source**: Live National Stock Exchange (NSE) API.
  - **Fallback**: yfinance real-time quote if NSE session throttles.

#### 7. `get_news_for_ticker(symbol: str, limit: int = 10) -> str`
- **Description**: Fetches recent company-specific news articles, headlines, and publication timestamps.
- **Implementation**:
  - Sends an HTTP request to the FinPilot News Microservice (`http://localhost:8002/api/news?symbol={symbol}`).
  - If the microservice is offline or times out (8s), it falls back directly to `nse_client.get_announcements(symbol)`.
- **Functional Readiness**:
  - **Status**: **Functional with Resilient Fallback**.
  - **Data Source**: Local RSS Aggregator (port 8002) $\rightarrow$ NSE Official Announcements Fallback.

#### 8. `get_corporate_filings(symbol: str, limit: int = 10) -> str`
- **Description**: Retrieves official exchange announcements, upcoming board meetings, and PDF links for annual reports directly from NSE corporate disclosures.
- **Implementation**:
  - Queries `nse_client.get_announcements(symbol)`, `nse_client.get_board_meetings(symbol)`, and `nse_client.get_annual_reports(symbol)`.
- **Functional Readiness**:
  - **Status**: **Fully Functional**.
  - **Data Source**: Official NSE Corporate Filings Feed.

#### 9. `get_shareholding_pattern(symbol: str) -> str`
- **Description**: Retrieves quarterly shareholding distribution and historical trends (Promoter, FII, DII, Public, Pledged shares).
- **Implementation**:

## 5. Evidence Integrity & Anti-Hallucination Contract

CYRO enforces a zero-tolerance policy for hallucinations through a four-tiered architectural contract:

1. **Context Views Isolation** ([`context_views.py`](file:///d:/cyro/FinPilot/india-trade-cli/web/cyro_engine/context_views.py)):
   - Specialists are provided *only* the specific fields in `StockResearchContext` relevant to their domain.
   - For example, `TechnicalAnalyst` only receives price/volume and options data, preventing prompt pollution.
2. **Deterministic Tool Evidence Generation**:
   - Every tool return dictionary includes `"evidence_type": "calculated"` or `"trusted_secondary"` and a clear `"source"` key.
3. **Evidence ID Whitelisting**:
   - System prompts dynamically inject the top 30 verified `evidence_ids`.
   - Agents are constrained to reference only existing IDs from the verified registry.
4. **Post-Committee Citation Validator** ([`graph.py`](file:///d:/cyro/FinPilot/india-trade-cli/web/cyro_engine/graph.py#L413-L451)):
   - A dedicated graph node filters out any claim evidence IDs that do not exist in `context.evidence_registry`.
   - Claims with non-existent citations have invalid IDs removed before emitting the final report event.
